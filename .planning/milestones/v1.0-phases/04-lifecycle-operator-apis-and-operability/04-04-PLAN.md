## Phase Goal

**As a** Correlia operator, **I want to** recover, expire, inspect, and mutate incidents through backend APIs and operability signals, **so that** the v1 operational surface is complete without a built-in frontend.

<objective>
Add low-cardinality Prometheus metrics at `/v1/metrics`, using the official `prometheus-client` package after the mandatory package-legitimacy checkpoint. Instrument the existing backend processing/lifecycle/task seams without adding high-cardinality labels or frontend code.

Purpose: Operators and maintainers need scrapeable operational counters/gauges for the complete ingestion, aggregation, notification, lifecycle, and worker surface.
Output: Dependency update, metric registry/helpers, `/v1/metrics` route, instrumentation calls, and targeted metrics tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Package registry -> runtime dependency | A new metrics package enters the trusted dependency set. |
| Processing/lifecycle state -> metrics registry | Event/incident data is reduced to labels and counters for a scrape endpoint. |
| Prometheus scraper -> `/v1/metrics` | Internal scrape client receives process metrics without auth. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04-SC | Tampering | `prometheus-client` install | mitigate | Blocking human checkpoint verifies exact PyPI package, official Prometheus docs, and source repo before `uv add`; no `[SLOP]` package allowed. |
| T-04-04-I | Information Disclosure | metric labels/text | mitigate | Label allowlist excludes host, service, fingerprint, group_key, incident_id, summary, message, raw payload, secrets, SMTP transcripts, and source blobs; tests scan rendered text. |
| T-04-04-D | Denial of Service | metrics cardinality | mitigate | Labels are bounded to event_type, reason, rule_name, effect, plugin_name, category, task_name; no per-object/per-incident labels. |
| T-04-04-R | Repudiation | metric event accounting | mitigate | Increment counters at durable seam boundaries: after accepted/rejected classification, after incident mutation result, after notification result, after task failure callback, and after worker health change. |
| T-04-04-E | Elevation of Privilege | metrics endpoint auth | accept | D-10/D-17 scope trusted internal APIs; do not add fake auth. Keep response non-secret and low-cardinality. |
| T-04-04-HIGH | ASVS L1 high-severity gate | metrics surface | mitigate | No high-severity threat is accepted; block if dependency checkpoint is rejected, if forbidden labels appear, or if metrics expose secret/raw content. |
</threat_model>
