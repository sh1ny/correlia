## Phase Goal

**As a** Correlia operator, **I want to** recover, expire, inspect, and mutate incidents through backend APIs and operability signals, **so that** the v1 operational surface is complete without a built-in frontend.

<objective>
Create the trusted internal `/v1` operator API cutover. Operators can list/filter incidents, inspect detail, acknowledge, manually close, and inspect safe rules/topology/plugin summaries through backend REST only.

Purpose: Correlia's product surface is REST/OpenAPI, not a built-in frontend. This plan turns lifecycle repository capabilities into operator workflows and moves existing routes under the locked `/v1` namespace.
Output: Incident API router, config status router, `/v1` route cutover, domain response/filter models, cursor helpers, and targeted API tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Trusted internal REST client -> FastAPI routers | Query filters, cursors, and action bodies are untrusted input even without built-in auth. |
| FastAPI routers -> PostgreSQL repository | REST actions mutate lifecycle state and expose incident data. |
| Config/plugin runtime state -> REST status responses | YAML-derived config and plugin registry data may contain secret-bearing options. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-S | Spoofing | `/v1` operator APIs | accept | D-10 explicitly scopes trusted internal APIs with no built-in auth; do not add fake API-key/session logic. Deployment proxy/network trust is the boundary. |
| T-04-03-T | Tampering | incident filters/cursors/action bodies | mitigate | Strict Pydantic request models, UUID parsing, bounded strings, SQLAlchemy expression building, and repository `WHERE status=OPEN` guards. |
| T-04-03-R | Repudiation | ack/close endpoints | mitigate | Require bounded `operator` and `reason` body fields where applicable; write compact context through repository functions. |
| T-04-03-I | Information Disclosure | incident detail/config/plugin responses | mitigate | Use allowlisted response models and tests scanning for raw payloads, plugin options, SMTP transcripts, credentials, tokens, secrets, stack traces, and source-specific blobs. |
| T-04-03-D | Denial of Service | incident listing | mitigate | Cursor pagination with `limit` bounded to 1..200; no offset scans or unbounded response tuples. |
| T-04-03-E | Elevation of Privilege | lifecycle close/open invariant | mitigate | Manual close uses repository transition helpers and preserves the PostgreSQL partial unique index; no reopening terminal incidents. |
| T-04-03-HIGH | ASVS L1 high-severity gate | REST surface | mitigate | No high-severity threat is accepted; block implementation if an endpoint exposes secrets, accepts raw SQL-like filters, or registers legacy aliases contrary to D-11. |
</threat_model>
