## Phase Goal

**As a** Correlia operator, **I want to** recover, expire, inspect, and mutate incidents through backend APIs and operability signals, **so that** the v1 operational surface is complete without a built-in frontend.

<objective>
Create the lifecycle mutation core for Phase 04. RECOVERY events bypass problem aggregation and notification dispatch, shrink object-level affected sets, resolve incidents only when the recovered membership empties the incident, and record bounded non-secret lifecycle context. Add repository support for idempotent acknowledgement and manual close so later REST endpoints call the same atomic transition layer.

Purpose: Recovery and operator lifecycle mutations must preserve the Phase 1 PostgreSQL one-open-incident invariant and the Phase 3 problem-only notification boundary.
Output: `LifecycleManager`, lifecycle repository functions, response/context contracts, ingress recovery branch, and targeted PostgreSQL/API/domain tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Icinga2 RECOVERY payload -> lifecycle manager | Source-derived host/service/fingerprint values become lifecycle mutation inputs. |
| Lifecycle manager -> PostgreSQL incident rows | Concurrent recovery/operator actions mutate affected sets and lifecycle status. |
| PostgreSQL decision_context -> API response/logs | Lifecycle context becomes operator-visible and must stay non-secret. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01-S | Spoofing | operator/recovery actor identity | accept | D-10 locks trusted internal APIs/no built-in auth for v1; plan does not add fake auth. Operator identity is recorded as provided and deployment trust boundary is documented in later REST plan. |
| T-04-01-T | Tampering | `resolve_host_recovery()` / `resolve_service_recovery()` | mitigate | Use SQLAlchemy bound values, JSONB containment, `WHERE status = 'OPEN'`, row locks, and `UPDATE RETURNING`; never interpolate host/service/cursor strings. |
| T-04-01-R | Repudiation | recovery/ack/close context | mitigate | Store reason, operator or source id, fingerprint, previous counts, and transition effect in bounded `DecisionContext` lifecycle notes. |
| T-04-01-I | Information Disclosure | lifecycle context and response envelope | mitigate | Pydantic validators and tests reject raw payloads, source-specific blobs, plugin secrets, SMTP transcripts, credentials, stack traces, tokens, and `plugin_config`. |
| T-04-01-D | Denial of Service | affected-set mutation | mitigate | Preserve existing affected host/service bounds and shrink sets under row locks; no unbounded context list or raw event retention. |
| T-04-01-E | Elevation of Privilege | duplicate active incidents after close/resolve | mitigate | Keep PostgreSQL partial unique index unchanged; terminal transitions use `OPEN -> RESOLVED/CLOSED` helpers and free the slot only after durable state change. |
| T-04-01-HIGH | ASVS L1 high-severity gate | lifecycle mutation surface | mitigate | No high-severity threat is accepted; the plan blocks implementation if tests reveal raw secret leakage, SQLite substitution, or an unguarded lifecycle status update. |
</threat_model>
