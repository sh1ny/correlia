## Phase Goal

**As a** Correlia maintainer, **I want to** validate plugin-core and incident lifecycle contracts before source ingestion exists, **so that** malformed or ambiguous alert data cannot enter later processing silently.

<objective>
Create strict domain contracts for normalized events, event types, severity, incident lifecycle state, acknowledgement metadata, and bounded decision metadata.

Purpose: Give later input, rule, persistence, and lifecycle slices one authoritative contract instead of scattered validation logic.
Output: Domain models/helpers with focused behavior tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Input plugin -> core domain | Later plugins will supply untrusted source-derived values to `NormalizedEvent`. |
| Core processing -> incident debug metadata | Processing facts may be persisted in `DecisionContext`; raw payloads and secrets must not cross this boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-07 | Tampering | `NormalizedEvent` | mitigate | `ConfigDict(strict=True, extra="forbid")`, explicit `EventType`/`Severity`, constrained tags, and timezone validator reject malformed/coerced values. |
| T-01-08 | Information disclosure | `DecisionContext` | mitigate | Stable typed envelope, forbidden secret/raw key validator, bounded note values, and tests for `raw_payload`, `credential`, `password`, `token`, `secret`, and `plugin_config`. |
| T-01-09 | Tampering | `IncidentStatus` | mitigate | Enum values exactly `OPEN`, `RESOLVED`, `CLOSED`; no `ACKNOWLEDGED` status so DB active uniqueness remains aligned with D-03. |
| T-01-10 | Elevation of privilege | YAML parser safety | mitigate | Domain models accept typed Python data only; this plan creates no YAML parser. Source assertions must find no `yaml.load(` introduced in domain files. |
| T-01-11 | SQL injection | Domain layer | accept | No SQL is generated in domain files; persistence plans own SQLAlchemy-only database access. |
| T-01-12 | API exposure | Domain layer | accept | This plan creates no routes or auth-independent mutation surfaces. |
</threat_model>
