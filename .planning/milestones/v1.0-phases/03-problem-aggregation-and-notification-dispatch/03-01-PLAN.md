## Phase Goal

**As a** Correlia operator, **I want to** have accepted PROBLEM events become durable topology-aware incidents and dispatch notification work only on durable threshold transitions, **so that** an alert storm produces one accurate incident and one controlled notification path.

<objective>
Create the durable aggregation slice for Phase 03: a typed `RuleDecision` plus `NormalizedEvent` becomes a PostgreSQL-backed open incident with bounded window state, replay-safe event_count semantics, first-threshold-transition detection, and compact safe outcome fields.

Purpose: This satisfies the incident-state half of the phase before any output work exists. PostgreSQL remains the source of truth for active incident identity, threshold/window facts, and no-repeat notification markers.
Output: Migration, model/repository extensions, `IncidentManager`, response/domain result models, and targeted PostgreSQL tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RuleDecision/NormalizedEvent → persistence | Typed but still untrusted event/config-derived strings enter SQL writes. |
| PostgreSQL row state → API response | Durable JSONB decision facts are exposed through compact response fields. |
| Concurrent ingress workers → one open incident row | Multiple writers can target the same `rule_name + group_key`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01-T | Tampering | `app/persistence/incidents.py` SQL writes | mitigate | Use SQLAlchemy bound values for rule/group/fingerprint strings; keep the partial-index predicate literal exactly as Phase 1 established. |
| T-03-01-R | Repudiation | threshold marker write | mitigate | Return `first_threshold_transition`, effect, replay, counted, and incident id from the same durable transaction result. |
| T-03-01-I | Information Disclosure | `DecisionContext` and envelope fields | mitigate | Persist only D-13 facts; validators/tests reject raw payload, credentials, tokens, secrets, SMTP transcripts, exception traces, rendered bodies, and plugin config. |
| T-03-01-D | Denial of Service | JSONB `window_state` growth | mitigate | Bound fingerprint map size with `MAX_WINDOW_FINGERPRINTS` and prune outside-window entries by event timestamp before write. |
| T-03-01-D2 | Denial of Service | notification storm | mitigate | Incident-side `threshold_crossed`/`notified_at` marker implements D-01/D-03/D-04 and returns another transition only once per open incident. |
| T-03-01-E | Elevation of Privilege | database substitute | mitigate | Tests and code stay PostgreSQL-only; no SQLite branch or fallback is accepted. |
</threat_model>
