## Phase Goal

**As a** Correlia operator, **I want to** send real Icinga2 alerts through normalization, enrichment, and deterministic rule evaluation, **so that** alert storms produce explainable decisions before durable incident mutation.

<objective>
Extend the Phase 2 ingress slice with topology YAML loading and pure topology enrichment.

Purpose: make the existing webhook response topology-aware before rule grouping uses topology tags.
Output: a configured static topology enricher that adds reserved `topology.*` tags, resolves conflicts deterministically, records diagnostics, and stays behind a plugin protocol.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Topology YAML file -> config loader | Operator-editable YAML crosses into process memory. |
| Config loader -> topology enricher | Compiled regexes/CIDRs and tags become runtime matchers. |
| Topology enricher -> ingress response | Infrastructure topology tags and diagnostics are exposed to API clients. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-S | Spoofing | topology tags in source payload | mitigate | Reserve `topology.*` for enrichment; topology wins conflicting source values and diagnostics record the source value plus override per D-08. |
| T-02-02-T | Tampering | `load_topology_config` | mitigate | Use `yaml.safe_load()`, `ConfigDict(strict=True, extra="forbid")`, reserved-tag validation, regex compilation, CIDR parsing, and overlapping-CIDR conflict rejection. |
| T-02-02-R | Repudiation | `EnrichmentDiagnostic` | mitigate | Include matched rule id/name, match source, added tags, overridden tags, and conflicts in response diagnostics per D-10. |
| T-02-02-I | Information Disclosure | topology response diagnostics | mitigate | Return only matched topology rule facts and changed tags; do not include raw YAML file content, full every-rule traces, filesystem paths, or settings values. |
| T-02-02-D | Denial of Service | regex/CIDR matching | mitigate | Compile regexes and parse CIDRs at load time; per-event enrichment uses compiled structures and stops after the first hostname or subnet match. |
| T-02-02-E | Elevation of Privilege | topology config | mitigate | YAML is declarative only; config cannot name Python modules, execute code, open files beyond the provided topology path, or access database sessions. |
| T-02-02-SC | Tampering | package installs | mitigate | No package-manager install tasks exist; PyYAML and stdlib `re`/`ipaddress` are already in the locked project stack. |
</threat_model>
