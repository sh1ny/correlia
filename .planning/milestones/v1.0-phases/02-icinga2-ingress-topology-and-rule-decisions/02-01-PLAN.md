## Phase Goal

**As a** Correlia operator, **I want to** send real Icinga2 alerts through normalization, enrichment, and deterministic rule evaluation, **so that** alert storms produce explainable decisions before durable incident mutation.

<objective>
Create the first complete Phase 2 slice: Icinga2 webhook request -> strict Icinga2 input plugin -> NormalizedEvent -> decision envelope response.

Purpose: prove ING-01 through ING-05 with real host/service state mapping and replay-tolerant fingerprints before adding topology and rules.
Output: a thin API path that accepts HARD Icinga2 host/service alerts, reports SOFT states as non-actionable diagnostics, returns a D-06 decision envelope, and performs no database writes.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Icinga2 client -> FastAPI `/webhooks/icinga2` | Untrusted JSON payload crosses into Correlia. |
| Icinga2 plugin -> core processing | Source-specific state becomes `NormalizedEvent`; raw Icinga2 fields must stop here. |
| App startup -> request dependencies | Lifespan-built processor is exposed through `request.app.state`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01-S | Spoofing | `/webhooks/icinga2` | transfer | Webhook authentication is outside this phase; response performs no durable mutation or notification in Phase 2, and deployment must network-restrict the route to Icinga2 until an auth requirement lands. |
| T-02-01-T | Tampering | `Icinga2WebhookPayload` | mitigate | Use Pydantic v2 `ConfigDict(strict=True, extra="forbid")`, host/service state cross-validation, timezone validation, and `NormalizedEvent.model_validate`. |
| T-02-01-R | Repudiation | `IngressDecisionEnvelope` | mitigate | Return deterministic `event_id`, `fingerprint`, `source_id`, `host`, `service`, `event_type`, `severity`, and `matched_rules` so accepted events can be tied to processing decisions. |
| T-02-01-I | Information Disclosure | ingress router errors and response body | mitigate | Return fixed `detail="ingest failed"` for unexpected exceptions; tests assert no raw payload, DATABASE_URL, token, password, secret, or exception text appears. |
| T-02-01-D | Denial of Service | webhook payload validation | mitigate | Reject malformed and extra fields before pipeline work; avoid DB calls and per-request config parsing in this plan. |
| T-02-01-E | Elevation of Privilege | plugin boundary | mitigate | Icinga2 plugin imports only domain contracts; no config-driven imports, no database sessions, no arbitrary YAML/code execution. |
| T-02-01-SC | Tampering | package installs | mitigate | No package-manager install tasks exist; any added npm/pip/cargo install must stop for the package legitimacy gate before execution. |
</threat_model>
