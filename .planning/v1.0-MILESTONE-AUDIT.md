### Flow 1 — Icinga2 PROBLEM to Notification

**Status:** passed

Path verified by integration checker:

`POST /v1/icinga2/events` → `Icinga2InputPlugin.process_payload` → `StaticTopologyEnricher.enrich` → `RuleEngine.evaluate` → `IncidentManager.apply_problem` → `record_problem_incident` PostgreSQL mutation → `session.commit()` before `TaskRunner.submit("notify", payload)` → `NotificationDispatcher.process` → `PluginRegistry.get_plugin` → `SmtpOutputPlugin.send_notification` → `record_notification_result`.

Requirements covered: ING-01, ING-02, ING-03, ING-04, ING-05, TOP-01, TOP-02, TOP-03, TOP-04, TOP-05, TOP-06, RUL-01, RUL-02, RUL-03, RUL-04, RUL-05, RUL-06, AGG-01, AGG-02, AGG-03, AGG-04, AGG-05, TSK-01, TSK-02, TSK-03, NOT-01, NOT-02, NOT-03, NOT-04, NOT-05.

### Flow 2 — Icinga2 RECOVERY to Lifecycle Resolution

**Status:** passed

Path verified by integration checker:

`POST /v1/icinga2/events` → input normalization → `EventType.RECOVERY` branch in ingress → `_apply_recovery` → `LifecycleManager.resolve_for_event` → `resolve_host_recovery` / `resolve_service_recovery` PostgreSQL row-locked mutations. RECOVERY bypasses `IncidentManager.apply_problem`; threshold and notification fields remain unset/zero.

Requirements covered: DOM-02, LCY-01, LCY-02, LCY-03, LCY-04, AGG-01, NOT-05.

### Flow 3 — Operator REST Lifecycle

**Status:** passed

Path verified by integration checker:

PostgreSQL incident rows → `/v1/incidents` list/detail → `list_incidents`, `get_incident_by_id` → `/v1/incidents/{id}/ack` via `ack_open_incident` keeps status OPEN and preserves active invariant → `/v1/incidents/{id}/close` via `close_open_incident` transitions OPEN to CLOSED and frees the partial unique active slot.

Requirements covered: PRS-01, PRS-02, PRS-03, API-01, API-02, API-03, API-04.

### Flow 4 — Operability and Status Surfaces

**Status:** passed

Path verified by integration checker:

`app.main.lifespan` wires sessionmaker, plugin registry, rules config, topology config, task runner, notify registration, Icinga2 processor, and lifecycle worker. Routes are backed by real app state:

- `/v1/health`: static liveness.
- `/v1/readyz`: database, settings/config, plugin registry/plugins, and lifecycle worker checks.
- `/v1/rules`: allowlisted rule summaries and config hash.
- `/v1/topology`: allowlisted topology summaries and hash.
- `/v1/plugins`: plugin status rows.
- `/v1/metrics`: private Prometheus registry rendering.

Requirements covered: FND-04, API-05, OPS-01, OPS-02, OPS-03.
