<objective>
Implement Phase 5 settings, fail-fast configuration, static Bearer authentication, and named public/protected route exposure for SEC-01, SEC-02, and SEC-03.

Purpose: Correlia's operator and sender HTTP surfaces must stop relying on trusted-network assumptions before additional compatibility workflows are exposed. This plan preserves D-01 through D-10 by making auth deterministic, token classes separate, and exposure controlled by named settings instead of path allowlists.

Output: Updated Settings fields and validators, a shared auth module, protected router wiring, conditional health/readiness/metrics exposure, and targeted tests proving there is no development-mode bypass.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External client → FastAPI router | Untrusted HTTP headers and requests reach route dependencies. |
| Environment → Settings | Deployment-provided strings become security policy and secrets. |
| Operator/sender token → route dependency | Bearer token proves access to operator or ingress route class. |
| Route module → app factory | Router dependencies and exposure flags determine whether a path is public or protected. |

## STRIDE Threat Register

High severity threats in this table are blocking: this plan is not complete until the mitigation tests named in the plan pass.

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|-----------|----------|----------|-----------|-------------|-----------------|
| T-05-01-S | Spoofing | High | `app/api/security.py` token checks | mitigate (blocking) | Use `HTTPBearer(auto_error=False)`, `SecretStr`, and `secrets.compare_digest`; test valid, missing, invalid, and wrong-class tokens for operator and ingress routes. |
| T-05-01-E | Elevation of privilege | High | Operator routers | mitigate (blocking) | Attach `Security(require_operator_token)` to incidents, rules, topology, and plugins routers per D-03; tests must prove unauthenticated access returns 401. |
| T-05-01-T | Tampering | High | `Settings` security configuration | mitigate (blocking) | Fail Settings validation when auth is enabled and required tokens are missing or empty per D-09; no environment-specific bypass. |
| T-05-01-I | Information disclosure | High | 401 responses and logs | mitigate (blocking) | Use the shared `Unauthorized` shape for all token failures per D-07/D-08/D-10 and do not include token class, token value, or header contents in responses or logs. |
| T-05-01-D | Denial of service | Medium | Auth dependency parsing | mitigate | Use FastAPI's `HTTPBearer` helper rather than custom regex parsing; malformed headers receive the same bounded 401 response. |
| T-05-01-SC | Tampering | Low | Package installs | mitigate | No new npm/pip/cargo packages are installed in this plan; if that changes, stop and run the package legitimacy gate before adding an install task. |
</threat_model>
