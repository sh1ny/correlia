## Phase Goal

**As a** Correlia operator, **I want to** send real Icinga2 alerts through normalization, enrichment, and deterministic rule evaluation, **so that** alert storms produce explainable decisions before durable incident mutation.

<objective>
Complete Phase 2 by adding strict YAML rule loading, deterministic first-match rule evaluation, human-readable group keys, and inspectable threshold/window decisions to the existing webhook path.

Purpose: prove RUL-01 through RUL-06 and make `/webhooks/icinga2` return a full normalization + enrichment + rule decision envelope.
Output: a rule engine slice that evaluates enriched `NormalizedEvent` instances without database access and reports matched/no-op, group key, threshold/window, and zero incident/closure/notification effects through the ingress response.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rules YAML file -> config loader | Operator-editable rule YAML crosses into typed config. |
| Rule config -> rule engine | Compiled regexes, actions, group-by fields, templates, and thresholds become runtime decision logic. |
| Rule engine -> ingress response | Decision facts are exposed to API clients. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03-S | Spoofing | rule action/plugin references | mitigate | Validate action names against `known_actions` and plugin references against `known_plugins`; unknown references fail load before processing. |
| T-02-03-T | Tampering | `load_rules_config` | mitigate | Use `yaml.safe_load()`, strict Pydantic models, duplicate name/priority rejection, regex compilation, summary-template variable validation, and group-by validation. |
| T-02-03-R | Repudiation | `RuleDecision` and `ThresholdDecision` | mitigate | Include matched rule, priority, group key, window bounds, threshold, counted fingerprints, crossed flag, and replay/skip reasons per D-21. |
| T-02-03-I | Information Disclosure | summaries and decisions | mitigate | Summary variables may reference only normalized fields and tags; response returns no raw Icinga2 payload, no settings paths, no plugin secret values, and no raw exception text. |
| T-02-03-D | Denial of Service | rule matching and threshold state | mitigate | Compile regexes at load time, sort rules once, first-match stops evaluation, enforce positive windows/thresholds, and count unique fingerprints within bounded windows. |
| T-02-03-E | Elevation of Privilege | YAML rule config | mitigate | YAML remains declarative; no Python imports, no expressions, no Jinja, no arbitrary code, and no database/session access in the rule engine. |
| T-02-03-SC | Tampering | package installs | mitigate | No package-manager install tasks exist; rule loading uses locked PyYAML, Pydantic, and Python standard library modules only. |
</threat_model>
