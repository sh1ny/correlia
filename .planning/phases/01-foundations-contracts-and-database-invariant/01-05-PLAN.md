## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet/client -> `/health` and `/readyz` | Unauthenticated clients can call health endpoints; no mutation or config disclosure is allowed in Phase 1. |
| API route -> Settings/readiness plumbing | Route dependencies read app state and call the database readiness helper created in Plan 01-01. |
| Service -> PostgreSQL | `/readyz` opens a database connection through the configured async sessionmaker and executes a fixed query. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Information disclosure | `/readyz` | mitigate | Return only `{"status":"ready"}` or `503 {"detail":"not ready"}`; tests assert no database URL, password, token, secret, or environment value appears. |
| T-01-06 | Denial of service | `/readyz` | mitigate | Delegate to Plan 01-01 `check_database_ready()` fixed `select 1`; keep `/health` independent of DB so liveness stays cheap. |
| T-01-07 | Tampering | route surface | mitigate | Register only the health router; tests assert no metrics/config-summary/ingestion/operator routes are present in Phase 1. |
| T-01-08 | Elevation of privilege | YAML handling | mitigate | Do not implement concrete YAML loading in this plan per D-18; health routes only expose status strings. |
| T-01-09 | API exposure | incident/operator mutation | accept | This plan creates no incident mutation, ingestion, acknowledgement, close, or list/detail API. |
</threat_model>
