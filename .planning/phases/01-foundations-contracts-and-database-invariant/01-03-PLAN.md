## Phase Goal

**As a** Correlia maintainer, **I want to** migrate PostgreSQL to the incident-state schema, **so that** active incident uniqueness is enforced by the database before aggregation code grows around it.

<objective>
Create the Alembic/PostgreSQL persistence slice: migration environment, first migration, SQLAlchemy incident model, and Testcontainers-backed schema/index verification.

Purpose: Make PostgreSQL the source of truth for incident lifecycle columns, JSONB metadata, and one-open-incident-per-rule/group uniqueness.
Output: Alembic setup, incident table migration, ORM model, and migration tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Migration config -> PostgreSQL | Alembic receives database URLs from env/CLI and must not persist secrets in config files. |
| Application model -> database schema | SQLAlchemy metadata and Alembic migration must not drift on status, severity, JSONB, or partial-index predicate. |
| Test runner -> Docker/PostgreSQL | Testcontainers spins up a real database for invariant verification. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-13 | Information disclosure | `alembic.ini`, `migrations/env.py` | mitigate | Do not write real database URLs or secrets; read runtime URL through env/CLI settings only; source assertions forbid `postgresql://`, `password`, `token`, and `secret` in config. |
| T-01-14 | Tampering | Incident uniqueness | mitigate | Create partial unique index `incidents_one_open_per_rule_group` with predicate `status = 'OPEN'` and Testcontainers duplicate-open tests. |
