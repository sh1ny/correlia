## Phase Goal

**As a** Correlia operator, **I want to** recover, expire, inspect, and mutate incidents through backend APIs and operability signals, **so that** the v1 operational surface is complete without a built-in frontend.

<objective>
Create the stale expiration vertical slice. The backend closes stale OPEN incidents from a lifespan-managed worker using PostgreSQL/database time and rule-specific window facts, while exposing worker health for readiness checks added later.

Purpose: Incidents must leave OPEN even when no future source event arrives, without Celery/Redis and without abusing the Phase 3 `TaskRunner` notification seam.
Output: DB-time expiration repository, lifecycle batch service, lifespan `LifecycleWorker`, settings, worker dependency, and targeted PostgreSQL/lifespan tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PostgreSQL incident state -> expiration worker | Stored window facts decide terminal lifecycle mutation without a source event. |
| Lifespan background task -> app readiness | Worker health becomes an operational signal. |
| Concurrent request processing -> expiration sweep | Requests and background sweeps can mutate the same incident rows. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-T | Tampering | `expire_stale_incidents()` | mitigate | Use `WHERE status = OPEN`, PostgreSQL database time, row locking/SKIP LOCKED, and `UPDATE RETURNING`; do not use app-clock comparisons or unchecked terminal writes. |
| T-04-02-R | Repudiation | expiration context | mitigate | Record `reason=expired`, rule/window facts, last update facts, and expired timestamp in bounded non-secret decision context. |
| T-04-02-I | Information Disclosure | worker health/readiness state | mitigate | Expose only `healthy`, safe category, timestamps/counts; do not store DB URLs, SQL text, stack traces, raw payloads, or plugin options. |
| T-04-02-D | Denial of Service | expiration scan | mitigate | Add `lifecycle_batch_size`, bounded interval, and skip-locked batch behavior; no unbounded table scan loop inside one transaction. |
| T-04-02-E | Elevation of Privilege | TaskRunner misuse | mitigate | D-08 keeps lifecycle scheduling outside `TaskRunner`; source assertions block `TaskRunner` expiration registration and Celery/Redis scheduler imports. |
| T-04-02-HIGH | ASVS L1 high-severity gate | background lifecycle worker | mitigate | No high-severity threat is accepted; implementation blocks on any unbounded scan, secret-bearing worker state, or app-clock stale predicate. |
</threat_model>
