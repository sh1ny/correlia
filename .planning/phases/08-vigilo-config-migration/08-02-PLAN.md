**Requirement IDs:** CFG-01, CFG-02, CFG-03, CFG-04, CFG-05, CFG-06, CFG-07

**Goal:** Build the standalone Vigilo/VDE config migration CLI that translates supported YAML into validated Correlia `rules.yaml`, `topology.yaml`, and `plugins.yaml`, while failing clearly on unsupported semantics and credentials.

## Planner Decisions Resolved

- Priority inversion: sort Vigilo rules by descending integer `priority` and assign Correlia priorities `1..N` in that order, so Correlia's ascending `RuleEngine` preserves Vigilo's higher-first evaluation. Reject duplicate or missing Vigilo priorities rather than inventing tie semantics.
- Report format: print human-readable errors to stderr and support optional `--report-path` JSON. The JSON shape is `{ok: bool, errors: [{domain, location, code, message, requirement}], generated: {rules, topology, plugins} | null}`. Do not log raw YAML values or credential values. Pin this with `test_report_shape`, including `generated: null` on failure.
- `tag_capture_groups`: consume the Plan 08-01 default-empty mapping. The migration emits `tag_capture_groups` only for hostname patterns with capture groups plus `target_tag`; literal-only generated hostname rules may omit the field.
- Unsupported-field catalog: maintain module-level constants in `scripts/migrate_vigilo_config.py` and reject every item listed in the catalog below during preflight, before transformation or output writes.
- SMTP TLS assumption: treat VDE `use_tls: true` or omitted `use_tls` as Correlia `start_tls: true`; treat explicit `use_tls: false` as `start_tls: false`. Document this in CLI help and `CONFIGURATION.md`.

- D-01 duplicate flag policy: reject repeated single-path CLI flags (`--rules`, `--topology`, `--plugins`, and `--out-dir`) with a custom argparse action rather than accepting argparse's default last-value-wins behavior.

## Unsupported-Field Catalog

Preflight must aggregate these as CFG-06 errors:

1. Rules: `rules[].window.min_hosts` presence, `rules[].is_dc_level` presence, missing/non-list/empty `match.severity`, missing/non-int `priority`, duplicate priorities, empty `actions`, non-string action entries, tag match values containing `*`, `?`, `[`, or `]`, tag keys that cannot be converted to valid `topology.*` keys, `window.group_by` entries that are neither normalized fields nor convertible to valid topology tag keys, `window.group_by: rule_name` even though that string is syntactically convertible to a topology key, and `output_summary` placeholders that are neither known normalized fields nor valid topology tag references after rewrite.
2. Topology: hostname entries with capture groups but no `target_tag`, hostname entries with no capture groups and no literal `tags` mapping to preserve, subnet entries missing `cidr`, `value`, or `target_tag`, and topology tag names that cannot be converted to `topology.*` keys.
3. Plugins: any top-level section other than `outputs` including `task_runner`, `inputs`, `llm`, `enrichers`, or `processor`; any output that is not an email output; any source class/module that cannot be mapped to the fixed generated class `app.plugins.outputs.email.SmtpOutputPlugin`; and plaintext SMTP credential keys `smtp_username`, `smtp_password`, `username`, or `password` under output config.
4. Inputs: directories, globs, missing files, and non-`.yaml`/`.yml` paths for `--rules`, `--topology`, or `--plugins` per D-01.
