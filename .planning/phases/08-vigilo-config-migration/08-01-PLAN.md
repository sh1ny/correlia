# Phase 8: Vigilo Config Migration - Plan 1

**Requirement IDs:** CFG-03, CFG-04

**Goal:** Add the runtime topology capture-group support required for migrated Vigilo hostname-derived tags to validate and enrich events correctly.

## Execution Context

- Read first: `.planning/phases/08-vigilo-config-migration/08-CONTEXT.md`, `.planning/phases/08-vigilo-config-migration/08-RESEARCH.md`, `.planning/phases/08-vigilo-config-migration/08-PATTERNS.md`.
- Existing analogs: `app/config/topology.py`, `app/processing/enrichment.py`, `tests/test_topology_enrichment.py`.
- This plan is Wave 1 and has no dependency on another Phase 8 plan.

## Planner Decisions Resolved

- Open question: `tag_capture_groups` is a strict `dict[str, int] = Field(default_factory=dict)`, not an optional field. Existing literal-only topology YAML may omit it; the migration emits it only when a Vigilo hostname pattern has both capture groups and a `target_tag`.
- D-07/D-09: `tag_capture_groups` keys must use the same `topology.` prefix rule as literal `tags`; values are 1-indexed integers validated first for `>= 1`, then against `pattern.groups` after regex compilation.
- D-08/D-09: Derived tags are applied after literal tags, use the same add/override/conflict diagnostics, skip `None` or empty group values, and reject non-empty values longer than the existing `TagValue` max length of 256.
- D-11: Subnet rules are intentionally unchanged and never accept `tag_capture_groups`.
