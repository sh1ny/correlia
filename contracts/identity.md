# Canonical identity v1

The executable boundary lives in `correlia_server/lib/src/event/identity.dart`; the public event entry
point exports it. [ADR 0021](../docs/adr/0021-canonical-event-v1-contract.md) freezes its semantics.
[identity-vectors.json](identity-vectors.json) contains independently calculated Python `struct`,
`hashlib` and `uuid` evidence, not values generated by the Dart implementation under test.

## Encoding

`E(pairs)` starts with a uint32 big-endian pair count. Each ordered pair contains uint32 big-endian
UTF-8 name byte length, name bytes, uint32 big-endian opaque value byte length, value bytes. Nested
E tuples contain their entire encoding. No terminator, separator, normalization, locale or BOM applies.
Reject duplicate names and malformed Unicode. Sort maps by unsigned UTF-8 bytes, not UTF-16 code units.

Identity component bytes are `00 || UTF8(value)` for originals up to 1024 UTF-8 bytes, otherwise
`01 || SHA256(UTF8(full original))`. Literal hash-looking strings remain raw components. Reject
original identity input over 1 MiB total before encoding/hashing, more than 128 fields, names above
128 Unicode scalars or an empty field set. Identity is never truncated.

| Result | Ordered pairs in E |
|---|---|
| Alert fingerprint | domain=correlia.alert.v1, tenant, namespace, source_kind, identity_fields=E(sorted tagged fields) |
| Native observation key | domain=correlia.native.v1, key=tagged source-native evidence |
| Alertmanager observation key | domain=correlia.alertmanager.v1, status, starts_at=presence, ends_at=presence |
| Fallback observation key | domain=correlia.fallback.v1, status, severity, reported_source_time |
| Observation UUID name | domain=correlia.observation.v1, source_instance, fingerprint, observation_key=complete key bytes, generation |
| Header transport key preimage | domain=correlia.transport.header.v1, source_instance, key=header text |
| Body transport key preimage | domain=correlia.transport.body.v1, source_instance, body_sha256=32 raw bytes |

All untagged scalar text is UTF-8. Fingerprints and transport keys are lowercase hexadecimal SHA-256.
Observation UUIDs are UUIDv5 using the fixed namespace `f36aac0f-16fa-46db-951b-bb578b323aed`, whose
network-order bytes are `f36aac0f16fa46db951bbb578b323aed`, followed by E(name) as above. UUIDs use standard
version/variant bits and lowercase canonical text. Generation is minimal uint32 decimal text.

This fixed UUID namespace is not the operator-controlled alert namespace. Alert namespace defaults to
source instance at source-context construction only. Explicitly shared alert namespaces give matching
fingerprints but distinct source-instance observation ids.

## Stable evidence

Alertmanager includes all labels, including severity, unless explicitly excluded. Validate full label
names and bounded collection size before exclusion; reject duplicate exclusions and an empty result.
A normalized severity value never independently changes a fingerprint.

Timestamp presence is `00` for absent, or `01 || UTF8(original timestamp text)` for present. At least
one valid source timestamp is required for Alertmanager. Fallback requires valid original reported
source time; no arrival-time fallback exists. RFC3339 has an explicit offset and at most nine fractional
digits; calendar rollover, leap seconds and invalid offsets fail. Normalized timestamps use UTC
seconds/nanos, but equivalent instants spelled differently remain different original evidence.

Native keys, fallback keys and transport keys have separate domains. Transport prefers a valid supplied
idempotency key; an invalid supplied key fails rather than falling back to a digest. Changing webhook
batching changes body-derived transport keys, not individual observation ids. Generation zero is initial
processing/replay; a positive generation changes the UUID and the event payload must retain original-id
lineage. The helper computes ids but does not allocate generations.

## Scope of proof

Vectors cover delimiter collisions, Unicode byte sorting, severity inclusion/exclusion, raw/hash tags,
native/fallback/Alertmanager evidence, generation zero/one/maximum and header/body domains. The reviewed
Alertmanager example has fingerprint
`09fc69bd0646d8e356c57b6c9b46256eda741ef8924425df1c9cce8ce2137b7f` and UUID
`86fe3b73-ec2d-5dd3-b104-11f2ec79469c`.

These are pure identity proofs, not durable dedup, state ordering, replay-effects or transport-storage
proofs. Those behaviors belong to subsequent changes; real Alertmanager → console → NATS proof remains
at milestone close. No consumers were published under the earlier example UUID whose namespace was
missing; the owner authorized replacing that draft before implementation.
