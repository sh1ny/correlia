# Proposal

## Why

Milestone **M1 - Walking skeleton** cannot start any feature work without a workspace: there is no Serverpod
project, no test tasks and no process model yet. This change lays that ground. It advances the M1 exit
criterion "`mise run check` and every test tier except `load` pass from a clean clone in WSL" (agent), and
the M1 risk "Serverpod 4.1 with embedded Postgres in tiered tests on Linux". It is constrained by ADR 0001
(one binary with `api`/`worker`/`all` roles), ADR 0002 (PostgreSQL in every run mode, embedded for
development and tests), ADR 0003 (Flutter web console) and ADR 0014 (Linux first; develop and test in WSL;
tasks must not assume WSL; never touch another Postgres). It advances no user-verified exit criterion.

A first attempt was reverted. Its lessons shape the scope: a small change, no hand-rolled shell test
harness, tier selection that really selects (`mise run test -- --tags db` must run the db tests), and a check
of consequences outside the touched files (the template's Dockerfile and Serverpod's shutdown order).

## What Changes

- A Serverpod 4.1.0 fullstack workspace at the repository root: a pub workspace with `correlia_server`,
  `correlia_client` and `correlia_flutter`, generated by `serverpod create` and trimmed. The greeting example,
  Serverpod Cloud storage, `docker-compose.yaml`, the template `.github/workflows` and the template
  Dockerfile are removed. The template's `.gitignore` rules that would hide the committed agent configs are
  not adopted.
- Pinned toolchain through mise: the Serverpod CLI 4.1.0, Go and buf, alongside the existing Flutter
  (Dart 3.13.7). Every tool resolves to a Linux path.
- mise tasks: `check` (the pre-push gate; what it runs is settled in the design), `test` (tiered; arguments
  such as `--tags db` select exactly what they name), `generate` and `analyze`. The `proto` task is deferred to `canonical-event-v1`.
- Test tiers by tag: `db`, `e2e`, `plugin` and `load` declared; real tests for fast, `db` and `e2e`. The
  embedded Postgres of the tests is the package's own, in its own data directory; a test proves that a test
  server killed with SIGKILL leaves nothing that stops the next run.
- Process roles: `api`, `worker` and `all`, selected without disturbing Serverpod's own command-line
  arguments; each role starts only its subsystems; `/livez`, `/readyz` and `/startupz` answer in every role;
  SIGTERM shuts down gracefully, with a hook for worker loops to stop before the database pool closes.
- A placeholder Flutter web console, built and served by the `api` role, with one widget test.
- The Serverpod MCP server in the Claude, Codex and OMP agent configs, launched through mise.

## Capabilities

### New Capabilities
- `process-roles`: how one Correlia binary is started in a role, which subsystems each role runs, its health
  endpoints and its graceful shutdown.
- `workspace-tooling`: the pinned Linux toolchain and the mise tasks developers and CI run (check, generate,
  analyze, tiered tests), including the isolation and recovery of the tests' embedded Postgres.

### Modified Capabilities
- none

## Impact

- New packages `correlia_server`, `correlia_client`, `correlia_flutter`; a root `pubspec.yaml` workspace.
- `mise.toml` (tools and tasks), `.gitignore`, `.mcp.json`, `.codex/config.toml`, OMP's config,
  `AGENTS.md` (Testing section: the test tasks now exist).
- Dependencies: `serverpod` 4.1.0, `serverpod_test` 4.1.0, `serverpod_flutter` 4.1.0 and their transitive
  packages. No Docker, no Redis, no CI.

## Decision Making

DECISION_MAKING: all
- **Source:** setting

### S1: Template scope

- **Choice:** Generate the fullstack template with database and webapp, without auth, Redis or website, and
  trim it: remove the greeting example, Serverpod Cloud storage, docker-compose and `.github/workflows`; keep
  the repository's own `.gitignore` rules for agent configs.
- **Rejected:** Keeping the template as generated: it carries CI workflows (no CI in M1, ADR 0014), Docker
  and Serverpod Cloud pieces Correlia does not use.
- **Reversal cost:** low
- **Important:** yes, it binds future changes (the package layout every later change builds on).
- **Chosen by:** user

### S2: Template Dockerfile

- **Choice:** Remove it until packaging in M10.
- **Rejected:** Fixing it now (Dart image, exec-form ENTRYPOINT, role by environment): packaging is M10, and
  an unused image is an untested artifact to maintain.
- **Reversal cost:** low
- **Important:** yes, the template version is wrong in ways users would see (no graceful shutdown).
- **Chosen by:** user

### S3: Go, buf and the proto task

- **Choice:** Pin Go and buf in mise now; defer the `proto` task to `canonical-event-v1`, where `.proto` files
  first exist.
- **Rejected:** A `proto` task over an empty tree (proves nothing); deferring the toolchains too.
- **Reversal cost:** low
- **Important:** no.
- **Chosen by:** user

### S4: Test tiers with real tests

- **Choice:** Fast, `db` and `e2e` get real tests; `plugin` and `load` are declared with no tests until a
  plugin exists.
- **Rejected:** Fast and `db` only (leaves health endpoints and shutdown unproven).
- **Reversal cost:** low
- **Important:** yes, binds future changes (the tier contract every later test follows).
- **Chosen by:** user

### S5: Process roles depth

- **Choice:** Role selection that never disturbs Serverpod's own arguments, a role-to-subsystem registry,
  health endpoints in every role and a shutdown hook for worker loops, all tested.
- **Rejected:** Parsing only; deferring roles to the first worker loop.
- **Reversal cost:** medium
- **Important:** yes, binds future changes (how every subsystem is started and stopped) and is visible to
  operators (how the binary is run).
- **Chosen by:** user

### S6: Serverpod MCP in agent configs

- **Choice:** Claude (`.mcp.json`), Codex (`.codex/config.toml`) and OMP.
- **Rejected:** Claude and Codex only.
- **Reversal cost:** low
- **Important:** no.
- **Chosen by:** user

### S7: Console in this change

- **Choice:** A placeholder page served by the `api` role, with one widget test.
- **Rejected:** The generated package only, unserved and untested.
- **Reversal cost:** low
- **Important:** no.
- **Chosen by:** user

### S8: Leftover embedded-Postgres cleanup

- **Choice:** Rely on Serverpod's own data-directory-based recovery and prove it with a test that kills a test
  server with SIGKILL and shows the next run starts cleanly.
- **Rejected:** An own cleanup tool (duplicates Serverpod); relying on Serverpod without a test.
- **Reversal cost:** low
- **Important:** yes, chosen on evidence read from Serverpod's source, not yet run.
- **Chosen by:** user
